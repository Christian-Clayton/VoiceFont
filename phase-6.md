# Phase 6: multi-style reference ownership and evaluation

**Status: planned, synthesis-dependent for listening claims.** Implementation specification after [Phase 3](phase-3.md) recording primitives and [Phase 5](phase-5.md) real speech. Reference-management work may start sooner, but audible style support may not be claimed before synthesis evaluation.

## Outcome

Keep distinct owner-labeled references for neutral, calm, serious, excited or friendly delivery, select a reference explicitly, and test whether the engine produces useful audible differences. The same voice may have several registers. Reference selection is portable; emotion transfer is not guaranteed by the profile format or OpenVoice's tone-color representation.

## Reference and capability policy

Start with neutral plus two owner-chosen comfortable styles. Retain the five-style goal as an expansion, not a forced recording requirement. Permit manual labels and custom style names with strict identifier validation. Never infer a person's emotional state from the audio.

Selection occurs once at the profile/service boundary. An adapter receives the resolved reference and supported controls; it does not independently guess another file. Default to explicit errors for unavailable styles. If the user opts into neutral fallback, response metadata states requested and effective styles and why fallback occurred.

Store style-reference availability separately from engine style-control capability and from demonstrated audible differentiation. Where the engine does not retain a delivery attribute, document that limitation rather than repeatedly demanding more exaggerated recordings. Pitch statistics are descriptive and may be absent for whisper; they cannot prove style distinctness.

## Acceptance criteria

- [ ] A profile contains at least three validated owner-labeled style references with source hashes and consent provenance; earlier raw takes are unchanged.
- [ ] Style add/replace is atomic, survives restart and preserves exactly one primary reference. Migration tests load supported older profiles and reject incompatible versions.
- [ ] Explicit selection reaches the actual reference recorded in output metadata. Traversal, missing reference, unknown style and revoked consent tests fail safely.
- [ ] Same-text outputs for each style are generated by the real backend and privately retained with listening notes. If listeners cannot distinguish styles, report that result and do not claim expressive control.
- [ ] Optional heuristic selection is deterministic, restricted to available styles and overridden by the user. Caches cannot mix voices, model versions, styles or withdrawn profiles.
- [ ] All recording, synthesis and evaluation runs stay local and offline after provisioning.

**Not included:** style interpolation, automatic emotion recognition, per-utterance style training, or custom TTS fine-tuning. Proceed to optional [Phase 8](phase-8.md) streaming when measured client latency warrants it; Phase 7 infrastructure is not a prerequisite for using styles.
